# Tasyir bmd v1.1 — مشروع أندرويد (إصلاح الكاميرا + حذف الزبائن)

## سبب المشكلة (الجذر)
النسخة القديمة (من WebIntoApp) كانت تفتقد `android.permission.CAMERA` في ملف AndroidManifest،
لذلك لا يظهر للتطبيق أي إذن "الكاميرا" في إعدادات الهاتف، ولا يمكن للصفحة فتحها أبدًا.
كما أن قراءة الباركود كانت تعتمد على مكتبة تُحمَّل من الإنترنت.

## ما تم إصلاحه
- إعلان إذن الكاميرا + طلبه وقت التشغيل + حوار "فتح الإعدادات" إذا تم الرفض نهائيًا.
- ماسح باركود/QR أصلي (ZXing) يعمل **بدون إنترنت**، مع مصباح، ورسالة نجاح/فشل لكل قراءة، ووضع مسح متواصل في شاشة البيع.
- معالجة أخطاء: لا توجد كاميرا، الكاميرا مشغولة، انهيار WebView، فشل تحميل الصفحة، رفض الإذن.
- تفعيل كاميرا الصفحة (ميزة قراءة اسم المنتج) عبر onPermissionRequest.
- إصلاحات WebView: نوافذ alert/confirm، اختيار الملفات (استيراد Excel / استعادة نسخة / صورة منتج)،
  حفظ النسخة الاحتياطية وCSV في مجلد التنزيلات، الطباعة، زر الرجوع.
- **حذف الزبائن**: زر 🗑 في قائمة الزبائن وفي نافذة الزبون، مع تأكيد، وتحذير مضاعف إذا عليه دين،
  ونسخة أمان تلقائية قبل الحذف. سجل المبيعات القديمة يبقى سليمًا.
- نفس اسم الحزمة ونفس مفتاح التوقيع ونفس عنوان الصفحة، فالتثبيت فوق النسخة القديمة يحافظ على البيانات
  (versionCode = 101). ومع ذلك خذ نسخة احتياطية من الإعدادات قبل التحديث.

## طريقة البناء (اختر واحدة)
1. **Android Studio**: File ▸ Open ▸ اختر هذا المجلد ▸ انتظر Sync ▸ Build ▸ Generate Signed... أو
   `Build ▸ Build Bundle(s)/APK(s) ▸ Build APK(s)` (التوقيع مضبوط تلقائيًا).
2. **سطر الأوامر** (JDK 17 + Android SDK + Gradle 8.7): `gradle assembleRelease bundleRelease`
3. **GitHub Actions**: ارفع المجلد إلى مستودع، وسيبني ملفي APK وAAB تلقائيًا (Actions ▸ Artifacts).

المخرجات:
- `app/build/outputs/apk/release/app-release.apk`
- `app/build/outputs/bundle/release/app-release.aab`

## الإصدار 2.0 (versionCode 103)
- ترحيل آمن للبيانات (db.v=2 + نسخة shopdb_v1_premigrate) دون تغيير عنوان الصفحة أو الحزمة أو التوقيع أو الترخيص.
- قائمة جانبية، المخزون والحساب، الموردون (صور في IndexedDB)، التحليلات (رسوم SVG)، العمال والرواتب التلقائية، حاسبة رأس المال، مستويات الأسعار، شاشة إعدادات جديدة، الوضع الداكن، الإنجليزية.
- شاشة بيع جديدة (تحديث جزئي، ±، تعليق سلال، ورقة دفع).
- PIN أصلي (PBKDF2 + مفتاح استرجاع + قفل تصاعدي)، طباعة بلوتوث ESC/POS (الإيصال يُرسم صورة فيدعم العربية)، دعم واتساب.
- لم يُنفَّذ: CameraX/ML Kit العائم، OCR بلا إنترنت، البصمة، أدوار الكاشير (ما زال الماسح ZXing).

### إعادة التصميم (واجهة فقط)
- `assets/htmlapp/js/ui.js`: أيقونات Lucide SVG محلية + نظام تصميم (CSS). أي إيموجي يُستبدل تلقائيًا بأيقونة عند العرض.
- لوحة تحكم جديدة، شريط تنقل بأسلوب iOS، نوافذ سفلية، حركات خفيفة. شاشة التفعيل الأصلية أُعيد تنسيقها فقط.

### دفعة الملاحظات (2.1 تجريبي)

### المتابعة عن بعد (Firebase، للقراءة فقط)
- انسخ محتوى `FIREBASE_RULES.json` إلى تبويب Rules في Firebase ثم Publish.
- من الإعدادات: «مشاركة المتابعة عن بعد» لإنشاء كود بصلاحيات؛ والمتابع من القائمة الجانبية: «متابعة متجر عن بعد».

### رواتب العمال — الصافي التلقائي
- لكل عامل: الراتب الأساسي + المكافآت (والإضافي) − السلف − الخصومات الأخرى = الصافي، مع مجموع صافي العمال النشطين أعلى الصفحة.
- يتحدّث تلقائيًا عند إضافة/تعديل/حذف عامل أو تسجيل سلفة/مكافأة/خصم أو صرف راتب.
- إن زادت السلف عن الراتب يُخصم المتاح فقط ويُرحَّل الباقي للدورة القادمة. الكود في `js/v4.js` (قسم رواتب العمال).
